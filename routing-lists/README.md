# Российские списки маршрутизации

Это открытый каталог исключений Reliable VPN для Windows и Android. Банки/платежи и госуслуги включаются по умолчанию в обычных режимах. Магазины/доставка, медиа и экосистемы включаются отдельно. Зоны `.ru`, `.рф`, `.su` — независимые выключенные переключатели.

25 октября 2026: поколение 3, **200 основных сайтов и 274 доменных правила** с дополнительными адресами сервисов. [Полный список и основания](TOP200.md). Текущий выбор категорий пользователя сохраняется; дополнительные категории автоматически не включаются.

Список предлагает прямой доступ, но **не утверждает, что каждый сервис блокирует VPN**. Это отобранные популярные и бытовые сервисы, а не измеренный рейтинг посещаемости. Официальные рекомендации отключить VPN, сообщения сообщества и профилактические исключения отмечены отдельно. Зависимости и доступность отличаются по сети. Целые зоны и общие CDN не добавляются в категории; конкретные адреса содержимого отдельного сервиса допустимы. Отключение одной категории не отменяет другую включенную категорию для родительского домена или включенную зону.

## Как добавить сервис

1. Измените `top200.tsv`: категория, сервис, основной домен и отдельные дополнительные домены. В наборе ровно 200 основных сайтов; заменяйте менее значимые позиции, а не расширяйте его автоматически.
2. В `top200.sources.json` укажите источник и дату для каждого дополнительного домена. Официальная документация предпочтительна; ссылки на данные сообщества должны быть закреплены по коммиту и не выдаваться за официальное подтверждение. Не переносите весь сторонний CDN, хостинг или доменную зону. Для рекомендации отключить VPN укажите конкретную проблему в `vpn_guidance`.
3. Увеличьте поколение в `top200.sources.json`, выполните `python routing-lists/build_top200.py`, затем `validate.py` и `test_validate.py`, обновите подпись и откройте pull request. `build_top200.py --check` проверяет воспроизводимость исходного каталога и таблицы. Проверка HTTPS-источника не равна проверке через VPN из российских сетей.
4. Если код редактировать неудобно, создайте Issue «Российское исключение» с доменом и описанием. Не прикладывайте токены, полную ссылку оплаты или историю посещений.

## Доставка

`routing-catalog.json` — самостоятельный артефакт подписанного релиза. Подпись Ed25519: `rvpn-routing-catalog-v1\0 || payload`. Публичный ключ совпадает с `root.pub`, приватный хранится вне репозиториев. Поколение увеличивается при каждом изменении. Старые артефакты не заменяются. Каталог плагинов и его ABI остаются прежними.

```sh
python routing-lists/publish.py --key /secure/offline/provider.key --generation 3 --output dist/routing-catalog.json
```

После подписи сохраните этот же файл как `routing-lists/catalog.signed.json` и приложите к релизу. Изменения источников требуют нового поколения. Публикация плагинов копирует этот подписанный файл без изменения; просроченный каталог необходимо обновить отдельной подписью с новым поколением. Каждый `latest`-релиз обязан содержать **оба** каталога. При релизе только списков скопируйте неизменённые артефакты последнего релиза плагинов, чтобы его URL обновлений продолжал работать. Новые списки применяются при сохранении настроек с переподключением либо следующем подключении.

Клиенты проверяют обновления раз в шесть часов и вручную, сохраняют последнюю проверенную версию без GitHub. Время проверки и срок каталога видны в приложении.

## Ограничения

Правила работают по системному DNS и IP. Общий IP может вывести соседний сайт напрямую; при известном конфликте побеждает VPN. DNS браузера/приложения через DoH/DoT не виден этому механизму. Помощник объясняет эти ограничения, не отключая защиту DNS самостоятельно. DNS-запросы идут через VPN, IPv6 для VPN блокируется до поддержки IPv6 туннелем. Выключение категории не отменяет включенную зону. Адреса хранятся только в памяти до истечения TTL, история посещений не собирается.
